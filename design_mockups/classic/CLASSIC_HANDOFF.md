# Classic Edition — デザイン・実装引き継ぎ

対象: File Organizer の追加GUI商品「**Classic**」（大人向け・落ち着いたGUI）。
作成: 2026-10-06、Cowork（Claude）上でユーザーと決定したデザイン。
この資料と同じフォルダのモック・スクリーンショット・装飾SVGだけで、決定したデザインを再現できるようにしている。

> **優先順位**: `CLAUDE.md`（安全ルール） ＞ `UI_DESIGN_HANDOFF.md`（ID・API・状態管理の契約） ＞ この資料 ＞ モックの細部。
> モックと既存の契約が衝突したら、契約を守り、見た目を近づける方法を考えること。

---

## 1. 商品としての位置づけ

- ココナラで「**機能は同じ、GUIを選べる**」形で出品する。Simple（現行の Workspace 版）が標準、Classic は別GUIのオプション商品。
- **整理機能・安全機構・API・データは Simple と完全に同じ。** 変えるのは見た目と画面構成だけ。
- Classic だけの付加価値は「サイドバー付きの画面構成（整理する / 履歴 / ヘルプ）」と「銅版画風のボタニカル装飾」。
- アプリ内でテーマを切り替える機能は作らない（購入した版で固定。切替できると別GUIを買う意味がなくなるため）。

## 2. デザインの方向性

- 雰囲気: 高級ホテル・書斎・クラシックカフェのような、落ち着いた大人向け。
- 色: ブラウン・生成り（紙のような背景）・深緑。
- 見出しは明朝体（Windows 標準の游明朝）、本文はゴシック（Yu Gothic UI）。Webフォントは使わない。
- 植物装飾: 「アンティークな植物図鑑の銅版画」「上質なカフェ／ホテルのメニューのボタニカル装飾」。
  - 3種類: **コーヒーの枝**（葉と実）、**オリーブの枝**、**シダ**。
  - 線の強弱・葉脈・版画風のハッチングあり。一部を画面外にクロップ。
  - メインUIより目立たせない（低い不透明度）。花柄・フェミニン・南国風・カフェの直接的なイラスト（カップ等）は使わない。

## 6. 推奨アーキテクチャ（Claude Code は計画段階で確認・提案すること）

**1つのコードで Simple / Classic をビルド時に切り替える。** 整理ロジックを2重に持たない。

- `app_config.py` に版（edition）の概念を追加: `simple`（既定）/ `classic`。
  - 版の決め方の例: 開発時は環境変数（例 `FILE_ORGANIZER_EDITION=classic`）、配布ビルドでは spec で版を埋め込む。Simple の既存挙動・既存テストは一切変えない。
- 表示名: Classic は `File Organizer Classic`（exe 名・ウィンドウタイトル・配布フォルダ名）。
- `web_app.py` の `/` で、版に応じて `templates/index.html`（Simple）か `templates/classic/index.html`（Classic）を返す。**変更はテンプレート選択と、テンプレートへ渡す値の追加だけ**。API・整理ロジックには触れない。
- 静的ファイル: `static/classic/classic.css`、`static/classic/classic.js`、`static/classic/botanical/*.svg`。`static/app.js` は両版で共用。
- ユーザーデータ保存先（`%LOCALAPPDATA%\MOMONGA_Lab\FileOrganizer\`）と多重起動ロックは**両版で共有**（同じ履歴を使える。両版の同時起動は防がれる）。
- PyInstaller: Simple のビルドはそのまま。Classic 用のビルド（別 spec か、spec のパラメータ）を追加し、`dist/File Organizer Classic/` を作る。Classic の配布物には Classic のテンプレート・静的ファイルだけを含める。

## 7. 実装時の制約とハマりどころ

### 7.1 守ること

- `UI_DESIGN_HANDOFF.md` の ID / name / value / dialog / fieldset / ARIA / hidden / `data-step` / API 契約を、Classic のテンプレートでも**すべて同じように持つ**（`app.js` を共用するため）。
- backend（`organizer*.py` / `local_state.py` / API）と `desktop_app.py` の安全機構は変更しない。`web_app.py` はテンプレート選択のみ。
- **`static/app.js` は原則変更しない。** Classic 独自の動き（画面切替・フォルダ集計）は `classic.js` に分ける。
- 新しい整理機能は追加しない（ファイルごとの選択・移動ボタン・確認の省略・テーマ切替などは作らない）。
- 文字列は `textContent` で描画（`innerHTML` にファイル名・パスを入れない）。
- 外部CDN・Webフォント・外部通信なし。`focus-visible`・`prefers-reduced-motion`・コントラストを維持。

### 7.2 画面切替（サイドバー）

- 3つのビュー（整理する / 履歴 / ヘルプ）を、新しいラッパー要素と `hidden` で切り替える（既存 ID の要素を消したり複製したりしない）。履歴の要素は常に DOM に存在させる。
- `#errorBanner` はどのビューからも見える位置（メイン領域の上部、ビューの外）に置く。Undo のエラーは履歴ビューで起きるため。
- 整理実行中（処理中）は、画面切替で処理状態が壊れないこと。切替自体は許可してよいが、戻ったときに進捗が正しく表示されること。
- 整理完了画面の「履歴」リンクは、履歴ビューへの切替（新しい機能ではなくナビゲーション）。
- 「直前の整理」カード: 既存 JS は `#historyRows` に全件をカードで描画する。Classic では最新の1件（先頭の `.history-card`）を CSS で強調する方法、または `classic.js` で DOM を読んで表示を補う方法のどちらか。`app.js` の変更が必要なら、最小限にして理由を報告する。

### 7.3 作成されるフォルダー一覧（Classic だけの表示）

- **API は変えない。** プレビュー後、`app.js` が描画した `#previewRows` の移動先セル（`.destination` のテキスト、例 `画像\IMG_2041.jpg`、拡張子別なら `jpg\photo.JPG`）から、区切り文字（`\` と `/` の両方）の前をフォルダ名として集計する。
- `classic.js` が `MutationObserver` で `#previewRows` / `#successRows` の変化を見て、件数と一覧を作り直す方法なら `app.js` を変えずに済む。
- 「作成されるフォルダー」は「移動先のフォルダーの種類数」。既存のフォルダーに入る場合も数に含まれる点に注意（ラベルは「移動先フォルダー」などにしてもよい。判断した場合は報告）。

### 7.4 ヘルプ画面（モック未作成）

- 固定テキストだけの画面。カード1〜2枚で、明朝の見出し・本文はゴシック。
- 内容（README / PRIVACY の事実に合わせる）: 使い方（3ステップ）、安全のしくみ（プレビューでは移動しない・同名は上書きしない・直前の整理は元に戻せる・サブフォルダーや拡張子なしファイルは対象外・PC内だけで処理）、データの保存場所とアンインストール方法。

### 7.5 既存の事情

## 10. 実装後の確定事項（2026-10-06、Claude Code）

### 10.1 データ保存先と多重起動ロックは Simple と共有（重要）

- Simple と Classic は**同じユーザーデータ保存先** `%LOCALAPPDATA%\MOMONGA_Lab\FileOrganizer\` を使う（`state.sqlite3` / `desktop.log` / `desktop.lock`）。
  - どちらの版で整理しても、同じ履歴が両方の版に表示され、直前の整理はどちらの版からでも元に戻せる。
  - 設定（整理方法・除外する拡張子）も共通。
- 多重起動ロック `desktop.lock` も共有するため、**Simple と Classic は同時に起動できない**（後から起動した側に「File Organizer はすでに起動しています。」と表示して終了する）。同じ履歴・ジャーナルを2つのプロセスが同時に書き換えないための安全機構で、意図した仕様。
- Classic をアンインストールするときに保存場所のフォルダーを消すと、Simple の履歴も消える（ヘルプ画面にも記載）。

### 10.2 版の切り替え

- `app_config.py`: `EDITIONS = {"simple": "File Organizer", "classic": "File Organizer Classic"}`、`EDITION`、`DISPLAY_NAME`。
- exe（frozen）は同梱の目印 `edition.txt` だけで版を決める（無い・不正なら simple）。環境変数は見ない。
- 開発時は環境変数 `FILE_ORGANIZER_EDITION=classic` で Classic 画面になる（未設定なら simple）。
- `web_app.create_app(..., edition=None)`: `/` のテンプレート選択（`index.html` / `classic/index.html`）と `app_name` の受け渡しだけ。API は共通。
- ビルド: Simple は `FileOrganizer.spec`（Classic のファイルを除外）、Classic は `FileOrganizerClassic.spec` / `build_windows_classic.bat` → `dist/File Organizer Classic/File Organizer Classic.exe`。
  Classic の配布物には `templates/classic/`、`static/app.js`、`static/classic/`、`edition.txt` だけを含める。

### 10.3 決定した表示

- 「作成されるフォルダー」は**「移動先フォルダー」**と表記（既存フォルダーへ入る場合も数に含むため）。完了画面は「整理後のフォルダー」。
- `static/app.js` は変更しない。そのため案内文の「整理を実行」「フォルダ」表記と、完了画面の表（ファイル / 移動先の2列）は共通のまま。
- パスやファイル名は省略（…）せず折り返す（安全ルール: パスを確認不能にしない）。
- 植物装飾SVGは `static/classic/botanical/` に、生成来歴メタデータ（C2PA の `<metadata>`）だけを除いてコピー。図形データは原本と同一。
- 幅 900px 以下はサイドバーをアイコンのみ（72px）にする。ボタンの文字は支援技術向けに残す。
