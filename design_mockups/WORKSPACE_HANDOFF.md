# Workspace GUI 刷新 — デザイン引き継ぎ

対象: File Organizer の Simple テーマ（`data-theme="simple"`）。
作成: 2026-10-03〜04、Cowork（Claude）上での提案・モック確認の結果をまとめたもの。
この資料と同じフォルダのモック／スクリーンショットだけで、決定したデザインを再現できるようにしている。

> **優先順位**: `UI_DESIGN_HANDOFF.md`（ID・API・安全な状態管理の契約） ＞ この資料 ＞ モックの細部。
> モックと既存の契約が衝突したら、契約を守り、見た目を近づける方法を考えること。

## 1. 経緯と今回のデザイン判断

### 1.1 現行 Simple 版の問題（分析結果）

- 白カード3枚を縦に積んだ「Webページ」構造。初期画面の高さ約1650px、プレビュー後は約1880px。
- 1100×800 のウィンドウで、最初に押すべき「整理予定を見る」が y≈860px にあり、スクロールしないと見えない。
- ステッパーの①②③と、各カードの番号バッジ（1・2）が重複している。
- 補足文が多く、見出しと本文のサイズ差も小さいため、すべてが同じ強さに見えて階層が弱い。
- disabled のメインボタンが「薄い青」で、壊れているように見える。
- プレビュー前・履歴なしの空状態カードが大きな面積を取っている。

### 1.2 比較した3案

| 案 | 内容 |
| --- | --- |
| A: Workspace | Windows 11 アプリ風の2ペイン。左=設定、右=プレビュー/結果。スクロールを減らす |
| B: Guided Flow | 今のステップだけを主役にする。大きなステッパー、目立つCTA、完了時の達成感 |
| C: Quiet Pro | 箱を減らし、余白・罫線・文字の強弱で構成する。モノクロ寄りで静かな上質感 |

### 1.3 採用方針

**構造は A（Workspace）、視認性は B（Guided Flow）、質感は C（Quiet Pro）。**

- **A から**: Windows デスクトップアプリらしい2ペイン／左=設定／右=プレビュー・進捗・結果／1100×800 で主要操作をできるだけスクロールなし／下部に履歴／Webページ感を減らす。
- **B から**: active / done / upcoming が分かるステップ表現／主要CTA（特に「整理を実行」）の視認性／完了時の達成感／今行っている操作が分かる状態表現。
- **C から**: 箱を増やしすぎない／影は控えめ／文字・余白・罫線で情報階層を作る／静かで上質／業務システム感ではなく販売ソフトらしい仕上がり。

## 3. 基準サイズとレスポンシブ

- **メイン: 1100×800**（pywebview のウィンドウサイズ。実際の Web 表示領域はタイトルバーと枠を除いた約 1084×761）。
  モックはタイトルバー 32px を含めて 800 にしているので、Web 表示領域は約 768px を想定している。
- 本番では高さを固定 px にせず、表示領域の高さに追従させる（例: アプリ全体を `height: 100vh` の flex 列にし、2ペイン部分は `flex: 1` / `min-height` を使う）。
  1100×800 では、主要操作（整理予定を見る／整理を実行／元に戻す）が**スクロールなしで見える**ことを目標にする。
- **幅 900px 前後以下: 1列に戻す**（設定 → プレビュー/結果 → 履歴の縦積み。縦スクロールは許容）。
- **800×600（最小ウィンドウ）でも壊れない**こと。横スクロールを出さない（既存UIテストが `scrollWidth <= innerWidth` を検査している）。

## 5. 見た目のルールとトークン

## 6. 実装時の制約

### 6.1 守ること

- `UI_DESIGN_HANDOFF.md` を優先する。既存の ID / name / value / dialog / fieldset / ARIA / hidden / `data-step` / API 契約を維持する。
- できるだけ **HTML / CSS 中心**で実装する。HTML は、囲み用の div の追加、要素の並び替え、ステッパーのヘッダー内への移動、静的テキストの追加・短縮まではよい（ID は変えない・消さない・重複させない）。
- `app.js` の変更は**必要最低限**。変更する場合は理由を報告する。
- backend（`web_app.py` / `desktop_app.py` / `organizer*.py` / `local_state.py` / `app_config.py` / spec）は変更しない。
- 新機能は追加しない。Cyber / Calm / Momo、テーマ切替、マスコットは今回実装しない。
- `focus-visible`、`prefers-reduced-motion`（transition を 0s にする既存テストあり）、文字コントラスト、色以外での状態表示を維持する。

### 6.2 既存コードの事情（ハマりどころ）

- `setButtonLoading()` はボタンの `textContent` を書き換えて戻すため、**ボタン内に置いた SVG などの子要素は消える**。ボタンの「→」やアイコンは CSS の `::before` / `::after` で付ける。
- `.step` の中身は `<span>1</span><strong>ラベル</strong>`。done のチェックは、数字を CSS で隠し（例: `color: transparent`）、`::after` やマスク画像で描く。番号テキスト自体は変えない。
- 整理完了時のステップ3の緑表示は、JS の `setStep(3)` のまま、CSS の `:has(#resultSection:not([hidden]))` などで切り替える。
- `#excludedCount` は JS が `「2 件」` を1つの文字列として書き込む（`#planCount` / `#previewFailureCount` は `<strong>` で数字だけ）。数字だけを大きくするには JS の変更が必要。
  → まず CSS だけで近づけ、必要なら「`renderPreview` で数字を `<strong>` に入れる」程度の最小変更を提案してから行う。
- 移動先セル（`.destination`）は「画像\IMG_2041.jpg」という1つのテキスト。フォルダ名だけを太字にすることはできない（モックも全体を同じ太さにしている）。
- `#historyRows` のカード構造は JS が作る（`history-card` / `history-meta` / `history-path` / `history-detail` / `details`）。
- UIテスト（`tests/test_simple_ui.py`）が検査していること: メインボタンの背景色が `rgb(49, 89, 184)`／800×600 で横スクロールなし／プレビュー表の `.table-wrap` の高さが 340px 以下（800×600 時）／reduced-motion 時に `.button` の transition が 0s／radio の矢印キー操作と focus outline。
  変更後もこれらが通ることを確認する。デザイン上どうしてもテストの値を変える必要がある場合は、理由を報告してから変更する。

### 6.3 モックと本番の差（了承済み）

- 32px のタイトルバーはネイティブ。モックでの再現は不要。
- 「除外 2件」の数字の強調は、上記の JS の都合で完全一致しない可能性がある。
- 進捗・エラー・ダイアログ・幅800px は未モック。上記の方針でトーンを揃えて作る。

## 7. 実装の進め方（推奨）

1. `UI_DESIGN_HANDOFF.md`・`templates/index.html`・`static/style.css`・`static/app.js`・`tests/test_simple_ui.py`・このフォルダのモックを読む。
2. **まず実装計画だけを出す**（変更するファイル、HTML 構造の変更点、`:has()` で切り替える状態、app.js を触るか、テストへの影響）。ユーザーの確認後に実装する。
3. 実装 → `pytest` → `node --check static/app.js` → 1100×800 / 800×600 のスクリーンショットで、`screenshots/` のモックと見比べる → PyInstaller ビルド → exe で Preview / 整理 / 履歴 / Undo / 多重起動 / 正常終了を確認。
4. 報告は CLAUDE.md の報告フォーマットで行う。モックと違う箇所があれば理由とともに明記する。
